# 质检清单：门禁式验收

## 为什么按"门禁"而不是"最后一起检查"

这条流水线上各道工序的**代价差了几个数量级**：

| 工序 | 单次代价 | 出错的代价 |
|---|---|---|
| 抓素材 | 几分钟 | 几分钟 |
| 镜头清单 / 资产库 / 序列描述 | 几十分钟（人力/模型） | 几十分钟 |
| **分段规划** | 几分钟 | **几小时 GPU 白烧** |
| **真机生成** | **每段几十分钟、全片数小时** | **数小时 GPU + 全部返工** |
| 后期（拼接/字幕/混音） | 十几分钟 | 十几分钟 |

所以原则是：**每道工序产出后立即验收，不合格绝不进入下一道**。把问题拦在便宜的那一侧。

配套的自动检查脚本：`scripts/qc_check.py`（能查的项自动查，查不了的留给人工目视）。

---

## 门禁总览

| 门禁 | 所在工序 | 验收物 | 不通过怎么办 |
|---|---|---|---|
| **G0** | 第二步 抓素材 | `frames/` `timestamps.txt` `audio/` `subs/` `meta/` | 调检测阈值/间隔重跑，几分钟 |
| **G1** | 第三步 镜头清单 | 镜头表（镜号/时间码/时长） | 修正时间码，别往下走 |
| **G1b** | 第四步 4a/4b **动作与说话人** | 镜头动作条 + 动作弧 + 台词分配表 | **回看动作条重写**——这是动作丢失与台词安错人的唯一防线 |
| **G2** | 第四步 资产库 | 资产库表 + 资产引用表 | **重做参考图**，这是最贵的一环 |
| **G3** | 第四步 序列描述 | 三层描述 + 检查清单 | 补写缺失项 |
| **G4** | 第六步 分段规划 | `plan.json` + 分段表 | 调策略/参数重跑，几分钟 |
| **G5** | 第七步 交付物 | 三份交付物 + **生成提示词副本** | 补写/改格式 |
| **G5b** | **提交生成之前** | **产出物清单 + 用户人工复核确认** | **拿到用户明确答复才可提交**；含糊时按最保守选项 |
| **G6** | 生成前 | **1~3 段试跑** | **停下来改上游，别继续烧 GPU** |
| **G7** | 后期 | 成片 | 逐项修 |

## G0 素材门

- [ ] **关键帧数量合理**：平均镜长落在 0.5~10 秒之间。少于 0.5 秒说明检测灵敏度太高（把运动当切镜），大于 10 秒说明太低（漏检了切点）——调 `-t` 重跑
- [ ] `timestamps.txt` **行数 = 关键帧张数**，一一对应
- [ ] 时间码**单调递增**，末值 ≈ 视频时长
- [ ] **音轨非静音**：若声称有台词却整轨接近静音，说明音轨提取失败或视频本无音轨
- [ ] **字幕来源确认**：有软字幕轨就抽字幕轨（最准）；画面有烧录字幕则跑 `extract_subtitles.py`；两者都没有而视频明显有对白 → 需要音频转写
- [ ] 元数据（分辨率/帧率/时长）与预期一致
- [ ] **盲区检查**：慢速推拉摇移镜头不会触发场景检测。如果某些时间区间异常空旷，用 `-i` 按固定间隔补抽交叉核对

---

## G1 镜头清单门

- [ ] 每个镜头都有**起止时间码与时长**，无空缺
- [ ] 各镜时长**总和 = 视频总长**（误差 < 0.1 秒）
- [ ] **无负时长、无重叠、无零长镜头**
- [ ] 镜头数与关键帧数对应（一镜一帧，或一镜多帧但已标注）
- [ ] 镜头编号连续，便于后续引用

---

## G1b 动作与说话人门（第四步 4a / 4b）

**这是整条流水线上最容易被跳过、却最容易导致"复刻出来跟原片差很大"的一关。**
只用单张静帧写提示词，**动作丢失与台词安错人都是必然结果**，而不是偶然失误。

- [ ] 每个镜头都抽了**多帧**（≥4；短镜 <1s 提到 6，长镜 >8s 提到 6~8），生成了镜头动作条
- [ ] **逐条看过**动作条——不是抽完就放着
- [ ] 每个镜头都写了**动作弧**：起始状态 → 中间运动 → 结束状态
- [ ] 动作弧里有 **「事件」** 字段，且写的是事件而不是画面外观
      （❌"巨树前的森林空地" → ✅"追蝴蝶时失足掉进树洞"）
- [ ] 标了**入场/出场**：有没有主体在镜头中途进入或离开画面
- [ ] 多镜头段的动作是**串成一条连续运动**，不是并列罗列几个画面
- [ ] **每条对白的说话人经过口型判断**（看对白条里谁的嘴在帧间开合），不是靠"谁在画面里"猜
- [ ] **画外音都标了 `off-screen`**，没有硬安到画面里的角色身上
- [ ] **台词分配表已建立**，且复检确认**每条台词只出现一次**
- [ ] 判断不了的说话人**如实标注待确认**，没有编造
- [ ] 源片有字幕/对白时，**已产出字幕资产**（说话对象 / 精确时间 / 停留时长 / 语速 / 语气 / 所属段）
- [ ] 字幕资产里**同一句的多次检出已合并**，起点取**最早**一次
- [ ] 字幕资产里**没有空白条目混入**（采样到无字幕的帧要剔除）
- [ ] 语速栏**标注为下限**，或用口型区间填了精确值；没有拿"下限"当真实语速去写提示词

自动检查（能查的）：

```bash
python scripts/qc_check.py --script ll_final_17.txt
```

会逐条列出**重复的对白**（含出现次数与段号），并对"描述里找不到任何动作动词"的段给出警告。

## G2 资产库门（最关键）

资产库错了，后面每一段都会错，而且要到生成结束后才看得出来。

### 覆盖面

- [ ] 源片里出现的**每个关键角色**都有资产条目
- [ ] 每个**关键道具**都有条目（反复出现、或在剧情中起作用的物件）
- [ ] 每个**反复出现的场景**都有条目
- [ ] 定了**全片风格**资产
- [ ] 反向核对：**通读一遍镜头清单**，逐镜确认画面里的角色/道具/场景在资产库里都有归属

### 参考图质量

- [ ] **清晰**：不是运动模糊帧、不是远景小图放大
- [ ] **正面或近正面**：角色最好是正脸或 3/4 侧脸（纯背影/纯侧影做锚点效果差）
- [ ] **遮挡少**：没有被其他元素挡住大半
- [ ] **没有字幕条压脸**：字幕遮挡会连带被学进角色外观
- [ ] **分辨率足够**：参考图短边不低于成片短边的 50%；宁可裁紧一点也不要放大充数
- [ ] 同一资产的多张候选图里选了**最干净的那一张**

### 描述与类型

- [ ] 每条资产的**固定描述写到了"照着能画出来"**的程度（体型/发型/服饰颜色+形制+材质/配饰），不是"穿着古装"这类空词
- [ ] **类型标注正确**（角色／道具／场景／风格）——类型决定引用时该强调"保持不变"还是"只借风格"
- [ ] 资产 ID **全局唯一且稳定**，后续所有引用都用同一个 ID

### 引用表

- [ ] **资产引用表已填全**：每条提示词（逐帧的与过渡的）都列出了引用的资产 ID 与槽位写法
- [ ] 没有任何一个关键资产在某镜"忘记引用"——这是最常见的退化点

---

## G3 序列描述门

- [ ] **过渡条数 = 关键帧数 − 1**（相邻帧之间一条不漏）
- [ ] 每条过渡都有：起始状态、**中间运动（含镜头类型+速度+幅度）**、结束状态、引用资产、**不变量**
- [ ] **首尾相接**：第 N 条的结束状态 = 第 N+1 条的起始状态
- [ ] 运镜描述**没有"缓缓移动""镜头运动"这类零信息量词**
- [ ] 对话**都标了说话人与起止时刻**
- [ ] 原片切点处**都标注了硬切**，并拆成两条而非糊成一条
- [ ] 一帧的多张关键帧（同镜多帧）描述**不矛盾**
- [ ] 用 `scripts/qc_check.py` 扫一遍骨架，把**未填写的空单元格**清掉

---

## G4 分段规划门

- [ ] **每段时长都在模型约束内**（达到最短、不超过最长）
- [ ] **设定秒数与实际时长对应正确**：设定值会被向上对齐到帧网格，实际时长 ≠ 设定值。核对分段表里的"实际时长"列是换算后的结果
- [ ] **覆盖率 100%**：源片每个镜头都归属到某个生成段，没有镜头被漏掉
- [ ] **总长偏差在可接受范围**（一般 ±10%；超出说明分段策略或档位选择有问题）
- [ ] **段边界落在源片切点上**（除非单个镜头超长需要拆分）
- [ ] 一镜一段的比例合理（保总长策略下快速剪辑的片段一定会合并，属正常）
- [ ] 段数不超过工具的段数上限

---

## G5 交付物门

- [ ] **三份齐全**：分镜脚本、制图提示词、复刻指南
- [ ] 交付说明开头有**复刻模式**一行（1:1 或列明变换项）
- [ ] 每段的提示词都能**追溯到具体的过渡描述**，没有凭空新写的内容
- [ ] 提示词长度**在目标工具的上下文限制内**
- [ ] 语言与格式符合目标工具要求
- [ ] 关键帧抽取时间与分段表锚点一致（**先定分段表再抽帧**，避免每条过渡都跨段）
- [ ] 源片若有真人清晰面部/品牌商标/版权音乐，复刻指南里**有版权提示**

## G5b 生成前人工复核门（**必须问用户，不可跳过**）

**在提交生成任务之前**，必须把三样东西交给用户人工复核，并**用结构化提问等用户明确表态**。
不要自行假定"应该没问题"——这三样东西一旦错了，代价是整轮 GPU 时间：

| 复核对象 | 位置 | 为什么必须由人看 |
|---|---|---|
| **字幕文本** | `字幕/lines/`（默认已放大 2 倍） | 脚本只给图不给字，转录靠人眼；**相邻重复字极易读漏**，漏字后句子往往仍通顺，语感校验失效 |
| **关键帧 / 分镜锚点** | `关键帧/`、`资产库/分镜*` | 锚点决定构图；带字幕的锚点会被模型照抄；锚点与提示词描述不一致必然导致构图跑偏 |
| **生成提示词** | `prompts/`（生成剧本） | 它是决定生成结果的**核心输入**，却最容易只留在工具侧不给人看 |

### 先产出清单，再让人指着清单复核

```bash
python scripts/build_manifest.py --project <项目目录> --source <源片路径>
```

会在项目目录生成 `产出物清单.md`：把所有输入产出列成一张表，逐条标出**是否必须复核**与该条的
**复核要点**。**复核相关的东西必须落在项目目录内**（不能在工具的 input 或临时目录里），否则
用户看不到、也就无从复核。

### 确认提问（用提问工具，不要用正文问）

一次问清三样，给出至少 5 个有实质差异的选项，推荐项放第一位：

| 选项 | 含义 |
|---|---|
| **三项均已复核通过，开始生成**（推荐） | 按当前文本/锚点/提示词提交全片 |
| 字幕文本需修改 | 用户指出具体条目，改完重出清单再问一次 |
| 关键帧/锚点需更换 | 某个锚点构图不对或带字幕 |
| 生成提示词需修改 | 动作事件、说话人绑定、`<Picture>` 编号、对白重复等问题 |
| 先只跑试跑段验证 | 不跑全片，先出 1~3 段验收（见 G6） |

**用户没有明确表示"通过"之前，不要提交生成任务。** 用户回答含糊时，按最保守的选项处理
（先跑试跑段），并在交付说明里写明。

### 自动核验：提示词是否符合官方格式

复核提示词时先跑：

```bash
python scripts/qc_check.py --prompt prompts/H3提示词_EN.txt
```

它会检查：六个 section 的顺序与命名、**section 正文是否全英文**（只有 `<d>` 内对白保留原语言）、
`<Picture N>` 是否越界（超出 `SCENE_INSTRUCTION.slots` 数量）、对白是否都绑定了说话人 `(Sx)`、
对白有无重复。

> 注意：`**时长**` / `**场景**` / `**动作描述**` 与 `slots` 里的槽位名是封装工具的**中文结构标记**，
> 本来就该是中文——核验器只检查六个 section 内部，不要把它们误判成违规。

### 中英双份的对齐检查

提交生成的是**英文版**，中文版（`prompts/*_CN*`）仅供复核。用户提出修改后：

- [ ] 改动**已同步到英文版**（不能只改中文译本）
- [ ] 改完**重新跑一次** `qc_check.py --prompt`
- [ ] 改完**重新出一次** `产出物清单.md` 再确认

### 清单自检

- [ ] `产出物清单.md` 已生成，且**没有"缺失"项**
- [ ] 三类关键复核对象（字幕文本 / 关键帧锚点 / 生成提示词）**都在项目目录内**、路径可打开
- [ ] `prompts/` 里有**中英两份**（`*_EN*` 提交用 / `*_CN*` 复核用）
- [ ] `字幕/` 目录内**只有 1 个字幕文件**（`.ass`），没有多余的 json/csv/md 副本
- [ ] 资产库里有**角色 / 服装 / 道具 / 场景 / 风格**五类（有则建，无则说明）
- [ ] 已用提问工具向用户确认，并拿到明确答复
- [ ] 用户提出的修改已落实并**重新出清单**再确认



**全片生成前必须先跑 1~3 段验收。** 这是整条流水线上最省时间的一条规则——上游任何一个错误，在这里暴露只要几十分钟，全片跑完再发现就是几小时。

- [ ] 试跑段**覆盖典型难点**：挑一个角色特写、一个多镜头段、一个场景最复杂的段
- [ ] **构图遵循度**：用与源片同时间点的画面做归一化互相关（NCC）。经验阈值——**> 0.8 优秀，> 0.5 可接受，< 0.3 说明没跟随参考帧**
- [ ] **角色一致性**：与资产参考图对比，体型/发型/服饰无漂移
- [ ] **结构缺陷目视**：高频密集结构（柱列、栏杆、雕花、文字）有没有"画两遍"或糊成一团
- [ ] **时长正确**：实际时长符合预期档位
- [ ] **音频**：若有对白，检查是否可辨、是否与原片时间码对得上
- [ ] 不合格时**回到上游改**（资产/描述/分段/工具参数），改完再试跑；**不要在明知不合格的情况下继续全片**

## G6 试跑门（效率守则的核心）

**G5b 已确认通过、且全片生成前，先跑 1~3 段验收。** 这是最省时间的一条规则——上游任何一个错误，
在这里暴露只要几十分钟，全片跑完再发现就是几小时。

- [ ] 试跑段**覆盖典型难点**：挑一个角色特写、一个多镜头段、一个场景最复杂的段
- [ ] **构图遵循度**：用与源片同时间点的画面做归一化互相关（NCC）。经验阈值——**> 0.8 优秀，> 0.5 可接受，< 0.3 说明没跟随参考帧**
- [ ] **动作事件是否真的进了画面**：提示词里写的"追蝴蝶""收拾行李箱""松手放下"这类事件，在生成画面里能不能看到（**这是只看静帧写提示词的典型翻车点**）
- [ ] **说话人是否对**：每个说话段的口型与画面里的角色是否对应
- [ ] **角色一致性**：与资产参考图对比，体型/发型/服饰无漂移
- [ ] **结构缺陷目视**：高频密集结构（柱列、栏杆、雕花、文字）有没有"画两遍"或糊成一团
- [ ] **画面里没有字幕/文字**：锚点若带字幕，模型会照抄
- [ ] **时长正确**：实际时长符合预期档位
- [ ] **音频**：若有对白，检查是否可辨、是否与原片时间码对得上
- [ ] **角色音色跨段一致**：跑 `scripts/check_voice_consistency.py`，同角色跨段距离应 **< 源片基线的 2.5 倍**。
      无音色锚定时实测会到 **18 倍**——这是"像两个人说话"的那种量级，**试跑段就能发现**
- [ ] 不合格时**回到上游改**（资产/描述/分段/工具参数），改完再试跑；**不要在明知不合格的情况下继续全片**

> **音色一致性要在 G2（资产库）就准备好**：源片有音轨时，先按角色抽出音色参考资产再写提示词。
> 等到成片才发现，就只能整片重跑。方法与两个必避的坑见 `references/voice_consistency.md`。

## G7 成片门

- [ ] 分辨率、帧率、时长符合交付要求
- [ ] **逐段抽帧与原片同时间点对照**，逐段确认构图与内容
- [ ] **段间接缝**：连续看一遍，有没有跳变、重复、倒放
- [ ] **音频对齐**：对白起止与原片一致；音轨无断裂、无突然静音
- [ ] **字幕**：位置/字号/描边与原片一致，无错字、无溢出画面
- [ ] 全片**没有黑帧、没有卡帧、没有音画不同步**
- [ ] 导出参数（码率/像素格式/色彩空间）符合平台要求

## 效率守则

| 做法 | 收益 |
|---|---|
| **便宜的档位试跑**（低分辨率 / 少步数 / 只跑 1~3 段） | 验收成本降一个数量级；确认无误再上高配 |
| **固定种子做对照实验** | 不固定种子的话，随机差异会盖过参数差异，实验等于白做 |
| **素材只抽一次** | 关键帧/音轨/字幕抽一遍缓存好，不要每轮重抽 |
| **先定分段表再抽关键帧** | 反过来会导致每条过渡都跨段，描述与生成段对不上 |
| **一次只改一个变量** | 多项变换一起做，出问题无法定位是哪一项导致 |
| **发现不合格立即停下改上游** | 明知有问题还继续跑，等于把错误成本乘上段数 |
| **能自动查的不要人工看** | 数量、时间码连续性、空单元格、档位换算用脚本查 |

### 快速止损信号

出现下面任一情况，**立刻停手检查上游**，不要继续生成：

- 试跑段的构图遵循度（NCC）低于 0.3
- 角色外观在试跑段之间就明显不一致
- 高频结构出现"画两遍"
- 段间出现重复内容或倒放
- 输出时长远超或远低于设定档位
