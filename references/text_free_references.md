# 参考图去字：为什么必须做，怎么做

## 问题

复刻时参考帧（锚点图、角色图、场景图）**必须不含任何文字**：

- **烧录字幕**：源片画面底部的中文字幕会被模型当成画面元素**照抄**，生成出一堆乱码汉字
- **常驻标题/水印**：短视频常见的左上角话题标题（如「当情侣一起出去吃饭：」）**每一帧都有**，
  躲不掉 —— 任何锚点都带着它
- **贴纸/角标/台标**：同理

**这不是"看着难看"的问题，是会被模型复制的问题。** 模型看到参考图里有字，就会在生成画面里
再画一遍，而它画的中文必然崩坏。

## ⚠️ 但有比"会被复制"更隐蔽的反效果：**抹得太狠，抹痕本身也会被复制**

这是实测踩过的坑，务必先看：

| 做法 | 结果 |
|---|---|
| **整条高斯模糊带**（把字幕带整幅宽糊掉） | 文字是没了，但**模型把那条模糊带照抄进了生成画面** —— 成片里字幕那一行出现一条糊带，叠加后期字幕非常难看。标题区的矩形模糊块同样被照抄 |
| **逐像素笔画修补**（只抹笔画的像素） | 没有带子了，但**留下清晰的字形深色残影** —— 描边比掩膜膨胀量大，没盖全，模型照着残影又画了一遍 |
| **笔画检测 → 紧致矩形**（检测规则写错） | 字幕干净了，**常驻标题却全部漏检** —— 标题常是"浅色字 + **白色描边**"，没有深色描边，而检测规则依赖"亮像素邻接**暗**像素" |

**正确做法（实测干净）**：

1. **常驻标题 → 固定框**（静止元素，位置固定，不需要检测）
2. **字幕 → 笔画检测取紧致矩形**（只和文字一样宽，**不是整幅宽**；整幅宽的带子容易被当成"结构"照抄）
3. 两者统一用 **`cv2.inpaint`（TELEA）** —— 填充是**周围内容的自然延续**，不是"一块糊"，
   模型没有可照抄的异常纹理

实测结果：标题区边缘能量从源片 600~780 降到 **5~12**（保留自然纹理但无文字结构；
对比纯模糊做法是 ~1.6，那是"糊成一片"），笔画检测复查残留矩形数 **0**。

> **可直接用**：`python scripts/detext_references.py --dir ./资产库 --verify`
> （内部已处理 Windows 中文路径 —— `cv2.imread/imwrite` 读不了非 ASCII 路径，
> 必须用 `imdecode/imencode` 绕过）

## ⚠️ 两种检测模式的取舍（**别只测一种样式就以为通用**）

同一套检测器，在**不同字幕样式**上的表现可以差很多。用 5 种样式实测
（把同一个字幕区域重新着色成不同样式来测）：

| 模式 | 白字+深边 | **黄字+深边**（短剧最常见） | 白字无描边 | 深字+亮边 | **金色渐变** |
|---|---|---|---|---|---|
| `--detect color`（颜色法） | ✅ | **❌ 静默漏检** | ✅ | ✅ | **❌ 静默漏检** |
| `--detect contrast`（默认，颜色无关） | ✅ | ✅ | ✅ | ✅ | ✅ |

**`color` 模式**假设"亮字 + 深色描边"，**最精准、修补后完全不留痕**，但换个颜色就废；
**而且它漏检是静默的** —— 返回 0 处，看起来像"这张图本来就没字"，字就这么进了参考图。

**`contrast` 模式**用形态学 top-hat/black-hat 找"与局部背景有对比的小结构"，
**不管颜色字体都能抓到**；代价是**会把场景细节（菜盘、热气、栏杆）也算成候选**，
于是遮得更多 —— 而**过度遮罩会把"整条模糊带被模型照抄"的老问题重新造出来**。

### 怎么选

| 情况 | 用哪个 |
|---|---|
| **知道**字幕是"亮字 + 深描边" | **`color`** —— 最精准，不会留条带 |
| 不确定样式 / 黄字金字 / 无描边 | **`contrast`** —— 先保证不留字 |
| 用了 `contrast` 后画面出现软条带 | 说明遮多了：**改用 `color`**，或把 `--sub-band` 收窄到文字高度 |
| 样式极特殊（发光、半透明、艺术字） | `--detect box`（整框 inpaint），或收窄 `--sub-band` |

### 两条硬规矩

1. **务必先跑 `--probe` 并打开可视化图看一眼** —— 红框是它认为的字幕位置。
   **漏检必须被发现**；误检多就换模式或收窄范围。
2. **过度遮罩不是"多抹一点无所谓"** —— 它等于把整条带糊掉，
   而实测证明**模型会把糊掉的那条带照抄进生成画面**。**宁可精准，不要图省事。**

### 关键实现细节

- **检测用宽松带、掩膜夹到字高**：对比度算子需要比字更大的核，带子太窄会漏检；
  但掩膜必须**纵向夹到"该行连通块的中位高度 × 1.8"**，不能取整行包围盒 ——
  否则会把行内混进来的场景细节一起遮掉
- 实测记录：给 240px 高的带做检测、不夹高度 → 遮出一大片糊区（等于造回条带问题）；
  把带子收窄到 110px 想避免 → 反而漏检（算子没余量了）。**正解是"宽松检测 + 紧致掩膜"**
## 做法：量准范围 → 修补 → 后期重新叠加

### 第一步：量准文字范围（**不要凭感觉估**）

实测过一次教训：凭感觉估的标题框 `(0,0,700,110)` 只盖住了标题的左半，资产里仍残留「…去吃饭：」的
残字。而标题实际范围是 `x 85–1030, y 55–145`——**比我估的宽了一半**。

正确做法：**裁一块带坐标网格的放大图，目视量取**：

```bash
# 裁左上角并放大，再用脚本画上坐标网格
ffmpeg -y -ss <任意时刻> -i src.mp4 -frames:v 1 \
  -vf "crop=1400:240:0:0,scale=1400:240" title.png
```

```python
# 在图上画网格（每 100px 一条），保存后自己看图读数
for gx in range(0, 1401, 100):
    d.line([(gx, 0), (gx, im.height)], fill=(255, 50, 50))
    d.text((gx + 2, 2), str(gx), font=F, fill=(255, 110, 110))
```

**为什么不用亮像素/白字检测自动定位**：实测不可靠 —— 明亮背景（窗户、天花灯）会被全部算成"文字
墨迹"，标题区的并集直接变成整幅画面。

**字幕带的范围**可以用 `extract_subtitles.py` 自动定位的那条带作起点（它靠时域变化找，比较准），
再向外留边距 —— 但**横向要按全宽遮**，因为长句字幕会铺得很宽。

### 第二步：用 inpaint 修补（不要涂黑、也不要大范围模糊）

```python
MASK_BOXES = [
    # (x0, y0, x1, y1, 填充来源)  坐标基于原片分辨率
    (40,  22, 1080,  178, "below"),   # 标题：取它下方同高的一条来填
    (0, 1170, 2560, 1370, "above"),   # 字幕带：取它上方同高的一条来填
]

def mask_text(path):
    im = Image.open(path).convert("RGB")
    W, H = im.size
    sx, sy = W / 2560.0, H / 1440.0          # 按原片分辨率换算
    for x0, y0, x1, y1, mode in MASK_BOXES:
        a, b = int(x0 * sx), int(y0 * sy)
        cx, cy = min(W, int(x1 * sx)), min(H, int(y1 * sy))
        bw, bh = cx - a, cy - b
        if bw < 2 or bh < 2:
            continue
        src = (im.crop((a, max(0, b - bh), cx, b)) if mode == "above"
               else im.crop((a, cy, cx, min(H, cy + bh))))
        src = src.resize((bw, bh)).filter(ImageFilter.GaussianBlur(14))
        im.paste(src, (a, b))
    im.save(path)
```

**要点**：

1. **用 `cv2.inpaint(TELEA)` 修补，不要涂纯色块、也不要大范围高斯模糊** ——
   纯色块或大面积模糊在参考图里都是明显的异物，模型会把它当画面结构画出来
   （见本文开头"抹痕本身也会被复制"）
2. **跨分辨率复用**：遮罩框按原片分辨率定义，用比例换算到实际图片尺寸（锚点图通常会缩放）
3. **所有参考图都要过一遍**：锚点、角色、场景、道具、服装 —— 任何一张带字都会污染生成

### 第三步：后期把文字加回来

被遮掉的字幕与标题**改在成片后用 ASS 叠加**，与字幕同一个文件：

- 字幕用底部居中的 `Sub` 样式
- 常驻标题用左上角的 `Title` 样式，时间轴设为全片（`0:00:00.00` 到成片总长）

```ass
[V4+ Styles]
Style: Sub,Microsoft YaHei,34,&H00FFFFFF,&H00FFFFFF,&H00141414,...,2,40,40,18,1
Style: Title,Microsoft YaHei,34,&H0050D0FF,&H0050D0FF,&H00202020,...,7,20,20,14,1
;                                                      ↑ Alignment 7 = 左上角

[Events]
Dialogue: 0,0:00:00.00,0:00:01.77,Sub,牛服务员,0,0,0,,这是两位的位置，请慢用
Dialogue: 0,0:00:00.00,0:00:32.71,Title,,0,0,0,,当情侣一起出去吃饭：
```

这样**画面里一个错字都没有**，所有文字都是后期精确排版的原文字 ✅

## 检查清单

- [ ] 确认源片有没有**常驻**标题/水印（不只是字幕）—— 逐帧看左上/右上/底部
- [ ] 用**坐标网格放大图**量准每处文字的范围，不要凭感觉估
- [ ] 遮罩框**按原片分辨率定义**，用比例换算到每张参考图
- [ ] 用 **`cv2.inpaint`** 修补（标题用固定框、字幕用笔画紧致矩形），不要涂纯色块、也不要整幅宽模糊
- [ ] **所有**参考图（锚点/角色/场景/道具/服装）都过一遍遮罩
- [ ] 重建后**逐张目视复查**：放大文字区，确认一个字都看不见
- [ ] 被遮掉的文字**在后期用同一个 .ass 加回来**（标题用左上角样式 + 全片时间轴）
- [ ] 用**视频片段**（不是单张静图）验证字幕渲染 —— 对静图用 `ass` 滤镜时时间戳恒为 0，
      永远只渲染第一条字幕，看不出真实时间轴

> **最后一条踩过坑**：用 `ffmpeg -i frame.png -vf ass=...` 测字幕，单张图没有时间轴，
> 滤镜按 t=0 渲染，于是任何时刻的测试都显示第一条字幕，看起来"时间全错"。
> 必须烧到视频上（`-i src.mp4 -vf "ass=...,scale=..."`）再抽帧比对。
