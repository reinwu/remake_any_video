# 字幕复刻

源片带字幕时，字幕必须当成**独立的一层**来处理——它和画面是两回事，混在一起做两件都做不好。

## 为什么不能让视频模型画字幕

文字渲染是视频/图像生成模型最弱的能力之一，中文尤其差：笔画会粘连、缺笔、多笔，字形"看着像"但不可读。而且字幕位置/出现时机无法精确控制。

**结论：生成阶段尽量不要字幕（或把字幕区域排除在外），字幕在后期按原片样式重新叠加。**

唯一例外：源片字幕已经烧录进画面、且**参考帧本身带字幕**——这时模型会"照抄"参考帧里的字幕（因为是画面的一部分）。但抄出来的字往往有形变，**不能当交付级字幕**，只能算画面纹理。

## 第一步：判断字幕类型

### A. 软字幕（字幕轨）

```bash
ffprobe -v error -select_streams s -show_entries stream=index,codec_name,language -of csv=p=0 input.mp4
```

有输出就是软字幕轨。**这是最好的情况**——文本与时间码都是精确的：

```bash
ffmpeg -y -i input.mp4 -map 0:s:0 -c:s srt subtitles.srt     # 抽成 SRT
```

如果用下载器抓取（本技能 `scripts/extract_shots.sh` 的 `subs/` 目录），还可能直接拿到平台字幕，比听写更准。

### B. 烧录字幕（画面像素里的）

ffprobe 查不到字幕轨，但画面上明显有字。需要**从画面里提取**——见第三步。

### C. 无字幕

跳过本节，但如果原片有台词/旁白而没上字幕，后期**建议补上**（很多平台算法偏好带字幕的内容），这时按原片的台词文本自己排版即可。

## 第二步：字幕样式分析（逐项记录）

对着关键帧看字幕，把这些维度记全——复刻字幕的像不像，全靠这一份描述：

| 维度 | 记录什么 |
|---|---|
| **位置** | 底部居中 / 顶部 / 画面中部；距画面下边缘约占画面高度的百分比 |
| **字体** | 黑体/宋体/圆体/手写体；字重（常规/粗）；是否为衬线 |
| **字号** | 字高约占画面高度的百分比（例如 4%~6%） |
| **填充色** | 纯白最常见，也有淡黄、品牌色 |
| **描边** | 描边色与宽度（最常见白字+黑描边，描边宽约字号的 6%~10%） |
| **阴影/发光** | 有无、方向、模糊程度 |
| **背景** | 无背景 / 半透明黑条 / 圆角胶囊底 / 渐变遮罩 |
| **断行** | 每行多少字、最多几行、是否按语义断句 |
| **动画** | 直接出现 / 淡入淡出 / 逐字打点 / 上滑；每条停留时长 |
| **标点** | 是否保留句末标点、是否用省略号 |

## 第三步：从烧录字幕提取文本与时间码

**不要逐帧看**——同一句字幕会横跨几十帧。正确做法是先按"字幕区域是否发生变化"分组，每句只需看一张图。

### ⚠️ 自动检测只是第一遍，**必须再跑一次密集扫描核对条数**

实测教训：一条 31.7 秒的片子，`extract_subtitles.py` 自动检出 **13 条**，
按 0.5 秒间隔逐帧读字幕带后发现**真实是 19 条** —— **漏了 6 条**。

漏掉的全是**短字幕**（只停留 0.4~0.5 秒的短句，比如「碗摆不开」「嘿嘿」「宝贝」「啊？」），
自适应阈值（均值 + k×标准差）配 0.3 秒采样正好把它们跳过去了。**还会误读**：
把 9.38s 的「菜也不好夹」看成了「我考虑真周到~」。

所以自动检测出来后**必须做这一步**：

```bash
# 每 0.5 秒抽一张字幕带，拼成带时间码标注的长图，逐帧读一遍
ffmpeg -y -i src.mp4 -vf "fps=2,crop=<w>:<band_h>:0:<band_y>,scale=1280:-2" f_%04d.png
```

第 N 张图对应时间 = `(N-1) × 0.5` 秒。**逐帧读一遍，与自动检测的结果逐条对齐**：
少了的补上、多了的删掉、文本不一致的以**放大图**为准（见下方"转录校验"）。

**密集扫描图也是给用户复核用的最好材料** —— 比逐条裁剪图更容易看出时间轴全貌。

用本技能的 `scripts/extract_subtitles.py` 自动做第一遍：

```bash
python scripts/extract_subtitles.py --video input.mp4 --out ./subs
```

它会：

1. 按固定间隔（默认 0.5 秒）抽帧
2. 裁出字幕区域（默认画面下方 22%，可用 `--region` 调整）
3. 对相邻采样做差异比较，**把画面相同的连续采样归为同一条字幕**，得到每条的起止时间
4. 为每条导出**一张裁剪图**（`subs/lines/line_0001.png` …）和一份**时间码表**（`subs/timing.json` / `subs/timing.csv`）

然后**逐张查看 `subs/lines/` 里的裁剪图，把文字填回时间码表**。看图的张数等于字幕条数（几十张），而不是总帧数（几千张）。

**时间码是近似值**：采样间隔决定了精度（默认 ±0.5 秒）。交付前可用更小的 `--interval` 精修首尾，或直接对着成片微调。

> 如果宿主没有读图能力，这一步无法完成——如实告诉用户"字幕文本需要人工转录"，不要凭空编造字幕内容。

## 转录校验（必做，别跳过）

### 真实事故：漏一个字，整条音画错位

复刻一条 25 秒短片时，原片字幕是 **「你能不能不要再这样」**（9 字），被录成了
**「你能不能再这样」**（7 字）——漏了「要」。后果不只是字幕错：因为**提示词是按错文本写的**，
生成的音频里说的就是错台词，只改字幕会造成音画不一致，最后只能整段重生成。

### 为什么会漏

| 层 | 事实 |
|---|---|
| 直接原因 | 转录靠**看图**——`extract_subtitles.py` 只产出时间码与裁剪图，给不了文字 |
| 为什么看图会错 | 从**缩放后的总览图**读：字幕文字原本约 40px 高，缩放后只剩约 36px |
| 为什么这个尺寸会错 | 「**不能不要**」里**两个「不」相邻**，在缩略图上容易糊成一个 |
| 为什么没被发现 | 漏字后的「你能不能再这样」**本身是一句通顺的中文** → 语感校验通过了 |
| 为什么自动检查没拦住 | ⚠ 告警**其实触发了**（7 字 / 2.75s = 2.55 字/秒 偏低），但被解释成"字幕悬挂" |

**根因：转录依赖人眼 + 缩放图，且漏字后的句子仍然通顺，语感校验天然失效。**

### 三道防线

1. **在放大图上逐字读**。`extract_subtitles.py` 现在默认 `--zoom 2`，把每条字幕裁剪图放大 2 倍
   后再保存，总览图也同步放大。**不要**在缩放后的缩略图上转录；字数多或字形相近时提到 `--zoom 3`。
2. **看语速合理性告警**。`build_subtitle_asset.py` 会对"字数 ÷ 停留时长"过低的条目报警，
   并**首先指向转录缺字**，而不是默认成"字幕悬挂"。看到告警先复核文本，别急着解释掉。
3. **换一个缩放比例二次复核**。同一张图换个尺寸再看一遍，两次独立读出的结果不一致就说明有问题。
   （这条是人眼转录唯一可靠的查错手段。）

### 试过但**不可靠**的方法（不要再用）

**用"墨迹宽度 ÷ 字数"反推是否缺字** —— 理论上很诱人（缺字会让每字宽虚高），实测不成立：

```
#4「我只是想和你好好说话」10 字 -> 墨迹宽 571px
#12「我不想再和你吵了」   8 字 -> 墨迹宽 299px
```

10 字比 8 字宽了近一倍，说明白色像素检测在不同光照下不稳定；而汉字宽窄差异本来就大
（我/一/样）。更糟的是反推结果会**给出相反建议**：漏掉两字的 7 字版本反而比正确的 9 字版本
更贴近均值。**宁可不加检查，也不加一个会误导人的检查。**

### 差错代价

转录错了，代价不只是改一行字：

- 字幕文件错了 → 要重烧
- **提示词里的 `<d>` 台词也错了 → 生成的音频说的是错台词 → 只能整段重新生成**

所以转录完成后、**写任何提示词之前**，先把字幕文本复核一遍。



提取完文本与时间码之后，**整理成一个文件**——它是后续检查、配音、字幕叠加、以及写提示词
绑定说话人的**唯一权威来源**。用 `scripts/build_subtitle_asset.py` 生成：

```bash
python scripts/build_subtitle_asset.py --transcribed subs/transcribed.csv \
    --out ./字幕 --name 字幕 --plan plan.json --time-map timemap.json \
    --play-res 864x480 --source "原片.mp4"
```

### 只产出**一个** `.ass` 文件

字幕以前会同时产出 `.json` / `.csv` / `.md` / `.ass` 四份，任何一次修改都要同步四个文件，
**极易出现"改了 json 忘了 ass"这类隐患**。现在只产出一份 `.ass`，它同时满足三个用途：

- **人看**：普通文本，记事本可读
- **机器读**：ASS 格式固定，解析稳定
- **直接可用**：ffmpeg 的 `ass=` 滤镜可直接烧录，无需转换

字段承载关系：

| ASS 位置 | 承载内容 |
|---|---|
| `Name` 字段 | **说话对象**（角色代号 + 全片统一编号），未判定写「待确认」 |
| `Text` 字段 | 台词（保留原语言） |
| `Start` / `End` | 精确时间码 |
| `[V4+ Styles]` | 字幕样式（字体/字号/填充色/描边/位置） |
| 每条紧邻的 `;` 注释行 | **语速下限 / 语气 / 检出次数 / 所属生成段** |

> `;` 开头是 ASS 的标准注释语法，libass 会忽略——**不会影响渲染**（已实测）。

### 时间映射

复刻成片的总长通常与源片不同（各段被拉到模型的时长档位上）。所以字幕时间**不能整体缩放**，
要按**分段边界做逐段线性映射**：源片 `[a,b]` 对应成片 `[ra,rb]`，段内按比例插值。
把映射表存成 JSON 用 `--time-map` 传入即可。

### 规则一：同一句在多次检测中重复出现时，**以第一次出现的时间为准**

角色说话慢、或台词长的时候，同一句字幕会横跨很多采样帧；采样抖动也可能让它在检测结果里
断成几条。这些**必须合并成一条，起点取最早的那次检测**。不合并的后果就是成片里同一句话
被当成多条对白处理——"同一句被说好几遍"这类 bug 的源头之一。

脚本会自动合并同文本的多次检测，并在报告里列出合并了哪些、各检出几次，便于核对。

同时它会剔除**空白检测**（采样到了没有字幕的帧）——这类条目在原始检测里占比可能很高，
不剔除会让人误以为字幕条数很多。

### 规则二：说话对象必须来自口型判断，不能猜

用 `scripts/extract_shot_frames.py --dialogue` 抽出的对白条，看**谁在帧间动嘴**。
判断不了就填「待确认」，**不要编**——安错人会让整段对白的音画关系全错。

### 语速只能当"下限"看

**字幕停留时长 ≥ 实际说话时长**（字幕上屏后会悬挂一段时间）。所以 `字数 ÷ 停留时长` 算出来的
是**语速下限**，不是真实语速。脚本会对"停留明显长于正常语速所需"的条目打 `⚠` 告警：

> 例：「啊完蛋了」4 字 / 停留 3.50s → 算出 1.14 字/秒，明显不合理——这是字幕挂着没走，
> 不是角色慢悠悠说了 3.5 秒。

要精确语速，需**按口型区间另填 `speech_span`**（嘴开始动到停下）。在拿到精确值之前：

- **不要**用这个数字去写提示词里的语速描述
- 交付说明里注明该栏是下限

### 语气

脚本先从标点粗推（`？`→疑问、`！`→感叹、`！！！`→惊慌、`~`→俏皮…）。更准的做法是
**看表情帧**——角色皱眉、张嘴幅度、身体前倾后仰都能反映语气。判定后填 `tone` 列覆盖自动值。

**字幕文件本身也是交付物**：`.ass` 里的 `Name` 字段与注释行就能让用户逐条核对说话对象、
时间、语速与语气，校验说话人时比看视频快得多——**不需要**再另外产出 json/csv/md 表格。

## 第四步：在后期重新叠加

**生成阶段不要字幕，成片后统一叠加。** 最可控的方式是用 ASS 字幕（能精确控制字体、描边、位置、动画），再用 ffmpeg 烧录。

### ASS 文件骨架

```
[Script Info]
ScriptType: v4.00+
PlayResX: 1920
PlayResY: 1080
WrapStyle: 2

[V4+ Styles]
Format: Name, Fontname, Fontsize, PrimaryColour, OutlineColour, BackColour, Bold, Italic, BorderStyle, Outline, Shadow, Alignment, MarginL, MarginR, MarginV, Spacing
Style: Sub,Source Han Sans SC,64,&H00FFFFFF,&H00000000,&H80000000,0,0,1,4,2,2,60,60,70,0

[Events]
Format: Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text
Dialogue: 0,0:00:01.20,0:00:03.40,Sub,,0,0,0,,第一句字幕
Dialogue: 0,0:00:03.40,0:00:05.80,Sub,,0,0,0,,第二句字幕
```

要点：

- `PlayResX/PlayResY` 设成**成片分辨率**，字号与边距才有稳定参照
- `Alignment=2` 是底部居中；`MarginV` 控制距底边距离
- 颜色是 `&HAABBGGRR`（**BGR 顺序，不是 RGB**），`00` 前缀表示不透明
- `BorderStyle=1` + `Outline=N` 是描边；`BorderStyle=3` 是背景框
- `Outline` 取 `Fontsize` 的 6%~10% 最接近常见的"白字黑边"

### 烧录

```bash
ffmpeg -y -i film.mp4 -vf "ass=subtitles.ass" -c:v libx264 -crf 16 -c:a copy out.mp4
```

字幕文件名与路径**不要含中文和空格**（部分 ffmpeg 构建在 `ass=` 滤镜里会因编码/转义失败）。先复制到工作目录改名为 `subtitles.ass` 再接。

### 对齐校验

叠完后抽几帧与原片同时间点的画面并排比较：位置、字号、描边宽度、出现时机是否一致。**位置偏差超过约 1% 画面高度就要调 `MarginV`**。

## 与分段规划的配合

- **分段表**里记录每段是否包含字幕、以及该段的字幕文本（供后期对时间码）
- **锚点帧**尽量选**不含字幕的画面**作为视觉锚点；实在避不开，要在提示词里说明字幕存在，否则模型会把它当画面元素描一遍
- 生成提示词里**不要**要求"画面中出现中文字幕"
- 若必须让模型渲染文字，写进 `MiniMaxH3PromptGuide` 的 `dialogue_lyrics_and_visible_text`，并在交付说明里标注"由模型生成、可能有误"
